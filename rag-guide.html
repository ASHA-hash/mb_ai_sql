📖 Part 1 — The Concept

What is RAG?

RAG stands for Retrieval-Augmented Generation. It is a method that makes AI give you accurate, specific answers instead of guessing — by letting the AI look up the right information first before answering.

❌ Standard AI (No RAG) — Closed-Book Exam

The AI only knows what it was trained on months ago. If you ask about your business data, your column names, or your business terms — it guesses. It may give wrong answers or say "I don't know."

Like a librarian who can't look at any books before answering.

✅ RAG-Powered AI — Open-Book Exam

Before answering, the AI quickly searches a private library of your data — your database tables, your business terms, past successful queries. Then it answers based on what it found.

Like a librarian who grabs the right book first, then answers.

⚙️ Part 2 — How It Works

Step-by-Step Flow

Here is exactly what happens every time you type a question in the AI Query panel:

1

You type a question

e.g. "What is the MTD net sales for Branch Delhi?"

2

RAG searches the memory library

The system searches three stores: Schema chunks (your 28 database views and their columns), Query Examples (past successful question→SQL pairs), and Glossary Terms (your business definitions like "Net Sales = SaleNetAmount").

3

The most relevant context is retrieved

The system finds, for example: the VwAISalesData view with columns SaleNetAmount, BranchAlias, SaleDate, plus a past example of a similar MTD query.

4

Context is attached to your question

The AI receives: your question + the relevant columns + the business definition of "MTD" + a similar past SQL as a guide.

5

AI generates a precise SQL query

Instead of guessing column names, the AI writes correct SQL using the exact columns from your schema. Result: accurate data, no hallucination.

🔍 Real Example

Your Question: "Show me unique customer count this month"

-- RAG retrieved this schema context automatically: -- View: dbo.VwAISalesData -- CustomerCode VARCHAR (unique customer identifier) -- SaleDate DATETIME -- SaleNetAmount DECIMAL -- Glossary: MTD = 1st of current month to today -- Past example: "customer count MTD" → COUNT(DISTINCT CustomerCode) SELECT COUNT(DISTINCT CustomerCode) AS UniqueCustomers FROM dbo.VwAISalesData WHERE SaleDate >= '2026-05-01' AND SaleDate <= '2026-05-11'

✅ Result: Accurate answer using the right column name — because RAG told the AI exactly which view and column to use.

✋ Part 4 — How to Use RAG Memory

Step-by-Step User Guide

📌 Opening RAG Memory

1
Log in to the Smart ERP Dashboard Open dashboard.html and sign in with your credentials.
2
Click the "🧠 RAG Memory" tab It is in the left navigation panel, below "🤖 AI Query". You will see three stat tiles: Query Examples, Glossary Terms, and Schema Chunks.

➕ Adding a Glossary Term

Use this when the AI doesn't understand your internal business language — like what "Net Sales", "PY", "LY", or "Branch" means in your context.

1
Go to the 📖 Glossary tab Inside RAG Memory, click the "Glossary" tab.
2
Type the Term and its Definition Term: LY Sales — Definition: Last Year Sales — same period last year using SaleNetAmount
3
Click "Add Term" It is saved immediately. The next AI Query you run will use this definition automatically.
💡
Tip: Use the Quick-Add buttons Common terms like MTD, YTD, QTD, Net Sales, and Branch are already written out for you. Just click the chip to pre-fill the form, then click "Add Term".

📚 Adding a Query Example

Examples are the most powerful thing you can add. When the AI sees a question similar to one it has seen before, it uses the stored SQL as a guide and gets the answer right almost every time.

A
Automatic (Recommended) Every time you run a successful query in AI Query, it is automatically saved as an example. You do not need to do anything. Over time, the AI gets smarter about your specific questions.
B
Manual — Go to the 📚 Examples tab Type the question, paste the correct SQL, and optionally add a note (e.g. "Use SaleNetAmount, not SaleGrossAmount").
C
From an AI result — click "💾 Save as Template" After running a query in AI Query, look for the "Save this query's SQL as a template" link at the bottom. One click saves it to both SQL Templates and RAG Memory.

❓ Part 6 — Common Questions

FAQs

QuestionAnswer
Do I need to set RAG up myself? No. The schema has already been indexed automatically (28 database views). RAG Memory is active the moment you start using AI Query. You only need to add Glossary terms to teach the AI your business vocabulary.
How many examples should I add? Start with the 5 quick-add glossary chips (MTD, YTD, QTD, Net Sales, Branch). After that, let the auto-save do the work. If you notice the AI repeatedly getting something wrong, manually add an example for that pattern.
Does RAG store my actual sales data? No. RAG only stores question → SQL pairs, column descriptions, and glossary definitions. It never stores rows of your sales or customer data.
What if the AI gives a wrong answer? If you know the correct SQL, go to RAG Memory → 📚 Examples, and add it manually with the right SQL. The next time a similar question is asked, the AI will use your correct version instead.
Can I delete an example that's wrong? Yes. Each example in the 📚 Examples tab has an ✕ button. Click it to remove. The AI will no longer use that example as a reference.
Is RAG the same as the SQL Templates? They are related but different. RAG quietly runs in the background to make every AI query more accurate. SQL Templates (📋 Saved SQL Queries in AI Query) are named shortcuts you click to run a specific SQL instantly — no AI generation needed.
💡

Recommended First Steps: Go to 🧠 RAG Memory → 📖 Glossary and click all five quick-add chips (Net Sales, MTD, YTD, QTD, Branch). This alone will make AI Query significantly more accurate for sales analytics questions.
